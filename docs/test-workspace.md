# พื้นที่ทดสอบบนเครื่อง

เปิดจากโฟลเดอร์โปรเจกต์ด้วย `npm run dev:test` แล้วเข้า **http://localhost:3002** หากเครื่องไม่มี native binding ของ Turbopack ให้เปิดด้วย `TEST_WORKSPACE_WEBPACK=1 npm run dev:test`

บน Mac ดับเบิลคลิก `test-workspace.command` เพื่อเปิดได้เช่นกัน ปล่อย Terminal เปิดไว้ระหว่างใช้งาน

| บัญชี                  | รหัสผ่าน       | ใช้สำหรับ                            |
| ---------------------- | -------------- | ------------------------------------ |
| `tester@deutsch.test`  | `TestOnly123!` | ทดลองบทเรียนและแบบฝึกหัด             |
| `tester2@deutsch.test` | `TestOnly123!` | ตรวจว่าเปลี่ยนบัญชีแล้วข้อมูลไม่ปะปน |

บัญชีเหล่านี้มีเฉพาะในพื้นที่ทดสอบ ไม่ได้สมัครใน Supabase จริง หน้าทดสอบมีแถบสีเหลืองบอกพื้นที่และบัญชี ระบบเก็บบัญชีและประวัติทดสอบใน `.tools/test-workspace-recovery.json` เมื่อปิดเซิร์ฟเวอร์ตามปกติ แล้วคืนเมื่อเปิดอีกครั้ง การรีเฟรช เปลี่ยนหน้า ออกจากระบบ แล้วเข้าบัญชีเดิมยังเรียนต่อได้

## ทดลองหลังแก้บัค

1. เปิด `npm run dev:test` และล็อกอินบัญชีทดสอบ
2. ทดลองบทเรียนตามปกติ; การแก้ source code แสดงผ่าน Next.js dev server
3. เมื่อต้องการเรียนต่อหลังปิดเซิร์ฟเวอร์ หยุดด้วย **Ctrl+C** แล้วเปิด `npm run dev:test` อีกครั้ง จากนั้นล็อกอินบัญชีเดิม
4. เมื่อต้องการประวัติว่าง หยุดด้วย **Ctrl+C** แล้วเปิด `npm run dev:test:reset` จากนั้นล็อกอินด้วยข้อมูลบัญชีทดสอบเดิม

ไม่มีปุ่มรีเซตสำหรับผู้พัฒนาเพิ่มในหน้าผู้เรียน ข้อมูลทดสอบเก็บเฉพาะในโปรเจกต์บนเครื่อง ไม่เหมาะสำหรับเก็บความก้าวหน้าจริง

## การแยกข้อมูล

เมื่อปิดพื้นที่ทดสอบตามปกติ ระบบสำรองบัญชีและแถวประวัติลง `.tools/test-workspace-recovery.json` (รูปแบบ `{ accounts, rows }`) อัตโนมัติ แล้วติดตั้ง migrations และ catalog ปัจจุบันก่อนคืนข้อมูลในการเปิดครั้งถัดไป ต้องล็อกอินใหม่เพราะ session เดิมสิ้นสุด แต่คู่ที่จับไว้และหลักฐานการเรียนยังอยู่ หากต้องการล้างข้อมูลให้ใช้ `npm run dev:test:reset`; ห้ามนำข้อมูลบัญชีจริงมาใส่ snapshot นี้

- เว็บทดสอบใช้พอร์ต 3002 ส่วนเว็บพัฒนาปกติยังใช้พอร์ต 3000; origin และ localStorage แยกกัน
- API ทดสอบฟังเฉพาะ `127.0.0.1:54329` ใช้ PostgreSQL จำลองผ่าน PGlite ในหน่วยความจำ และเขียน snapshot เมื่อปิดตามปกติ ไม่มี Docker/Bun เพิ่ม
- เบราว์เซอร์เรียก API ผ่าน `/__test-db` บน origin เดียวกับเว็บ; Next.js ส่งต่อไป API บนเครื่อง ไม่ต้องเรียกข้ามพอร์ตจากเบราว์เซอร์
- ใช้ SQL migrations ใน repository รวม schema, content seed, RLS, learning RPC และ lesson states; ไม่อ่านหรือคัดลอกประวัติบัญชีหลัก
- launcher กำหนด Supabase URL/key เป็นค่าท้องถิ่นแทน `.env.local` และปิด legacy lesson import; ไม่แก้ `.env.local` และไม่ใช้ `DATABASE_URL`
- Auth storage เปลี่ยนทุกรอบ จึงต้องล็อกอินใหม่หลังเปิดเซิร์ฟเวอร์; UUID บัญชีคงเดิมเมื่อคืน snapshot และเปลี่ยนเมื่อสั่ง reset
- build cache แยกใน `.tools/test-workspace-next`; ไม่หยุดเซิร์ฟเวอร์อื่น หากพอร์ตถูกใช้งาน คำสั่งจะหยุดพร้อมข้อผิดพลาด
- test-workspace flag ถูกปฏิเสธเมื่อ production build; ไม่ต้องตั้งค่าทดสอบบน Vercel

เลือกรันบนพอร์ตอื่นได้ เช่น `TEST_WORKSPACE_PORT=3003 TEST_WORKSPACE_API_PORT=54330 npm run dev:test` ต้องใช้พอร์ตที่ต่างกันและไม่ใช้ 3000

เปิดพื้นที่ทดสอบครั้งละหนึ่งชุด เพราะใช้ build cache ทดสอบร่วมกัน ปิดด้วย Ctrl+C ก่อนเปิด browser test อัตโนมัติ เว็บพัฒนาปกติพอร์ต 3000 เปิดควบคู่ได้

## ขอบเขตผลทดสอบ

SQL/RLS และ flow ของแอปใช้ implementation จริง แต่ Auth และ REST เป็น adapter ท้องถิ่นที่รองรับ API ที่แอปใช้ ไม่ใช่ Supabase server ครบชุด การสมัครบัญชี ยืนยันอีเมล ส่งอีเมล และพฤติกรรมบริการ hosted Supabase ไม่ได้จำลอง; ใช้สองบัญชีที่เตรียมไว้ การทดสอบบริการจริงและ deployment ยังเป็นงานแยกต่างหาก

คำสั่งเลือก Node.js 20.9+ ใน `.tools` หรือ PATH อัตโนมัติ ไม่เปลี่ยน runtime ของเว็บจริง

ตรวจ adapter ด้วย `npm run test:workspace` และตรวจเว็บตั้งแต่ล็อกอินถึงเริ่มรอบใหม่ด้วย `npm run test:workspace-browser` (ต้องใช้ Node 20.9+; browser test ใช้ Chrome บน macOS หรือตั้ง `CHROME_PATH`) browser test เปิดพอร์ต 3032/54339 และปิดเซิร์ฟเวอร์ของตัวเองเมื่อเสร็จ

Next.js สร้าง `next-env.d.ts` ที่ root แม้ใช้ cache/tsconfig แยก launcher คืนไฟล์เดิมเมื่อปิดตามปกติ ถ้าถูกบังคับปิดด้วย SIGKILL ให้เปิดและปิด dev server ปกติเพื่อสร้าง type declarations ใหม่

## เปิดจากโทรศัพท์ใน Wi-Fi เดียวกัน

launcher เปิดเว็บบน `0.0.0.0:3002` และพิมพ์ URL ของ IP คอม เช่น `http://192.168.1.43:3002` ให้ใช้ URL นี้ในโทรศัพท์ โดยคอมกับโทรศัพท์ต้องอยู่ Wi-Fi เดียวกันและคอมต้องเปิดเซิร์ฟเวอร์ไว้ `localhost` บนโทรศัพท์หมายถึงโทรศัพท์เอง ไม่ใช่คอม หาก IP คอมเปลี่ยนให้เปิด launcher ใหม่เพื่ออัปเดต allowed origins

API ฐานข้อมูลยังฟังเฉพาะ loopback ไม่เปิดพอร์ต 54329 สู่เครือข่าย ทุกคำขอจากโทรศัพท์ผ่าน `/__test-db` ของเว็บ และรับเฉพาะ origin localhost กับ IP ที่ launcher ตรวจพบ บัญชี/สถานะทดสอบเดิมใช้งานร่วมกันบนคอมและโทรศัพท์ได้ แต่อุปกรณ์ใหม่ต้องล็อกอินก่อน
