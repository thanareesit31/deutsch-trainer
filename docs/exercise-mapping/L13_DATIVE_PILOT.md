# L13 Personalpronomen im Dativ: mapping รายข้อและต้นแบบ

วันที่ตรวจ 20 ตุลาคม 2026. งานชุดแรกตามแผน A1.3 ใช้หัวข้อเดียวเพื่อกำหนดวิธีตรวจแหล่ง สร้างโจทย์ และทดลอง UX ให้ครบหนึ่งรอบ ก่อนขยายหัวข้ออื่น

การขยาย Es gibt และ Verben พร้อมรอบพื้นฐาน L13 บันทึกแยกใน [L13_ES_GIBT_VERBEN_PILOT.md](L13_ES_GIBT_VERBEN_PILOT.md). เอกสารนี้ยังอธิบายเฉพาะคลัง Dativ และหลักฐานที่ตรวจสำหรับหัวข้อนี้

เปิดเล่นในบัญชีทดลองได้แล้ว: เมนูแบบฝึกหัด → ทดลอง Dativ · L13 หรือ `/practice/L13/grammar/dativ-pilot`. ต้องเป็น tester/tester2 ใน `dev:test`. หน้าเว็บฝังต้นแบบเดียวกันและเก็บผลในเบราว์เซอร์แยกตาม user ID; ผลยังไม่เข้า Progress หลัก. `scripts/exercise-mapping/verify-test-account.mjs` ตรวจ login, ทางเข้า, resume, การสลับบัญชี และหน้าจอมือถือกับเซิร์ฟเวอร์ทดสอบจริง

เมื่อ 20 ตุลาคม ปรับโจทย์ 11 ข้อที่เคยมี `(ich)` หรือคำบอกบุคคลในวงเล็บท้ายประโยค ให้แสดงสถานการณ์ภาษาไทยสั้น ๆ เหนือประโยคเยอรมัน. ข้อที่มีผู้ถูกอ้างถึงในข้อความเยอรมันอยู่แล้วใช้ข้อความนั้น. ข้อความที่เปลี่ยนมี `question.version = 2`; คำตอบและตัวเลือกเดิมคงเดิม. รอบที่ทำค้างแสดงคำสั่งใหม่ขณะเก็บ snapshot ของ attempt และลำดับตัวเลือกเดิมไว้

เวอร์ชันปัจจุบันคือ `question.version = 3` สำหรับ 11 ข้อนี้. หลังผู้ใช้ทดลองแล้วพบว่ากล่องสถานการณ์ยังทำให้โจทย์แยกเป็นสองส่วน จึงเขียนผู้ที่สรรพนามอ้างถึงไว้ในประโยคเยอรมัน เช่น `Ich finde den Markt schön. Der Markt gefällt ___.` ต้นแบบแสดงประโยคต่อเนื่องเพียงชุดเดียว; ไม่มีวงเล็บหรือกล่องบริบท. นี่เป็นรูปแบบโจทย์เว็บที่ออกแบบใหม่. Momente Kursbuch กำหนดเป้าหมายไวยากรณ์ และ Arbeitsbuch 13/8a ให้แนวเติมสรรพนามจากบริบท. ตัวเลือกและเฉลยเดิมยังใช้ได้; รอบที่ค้างใช้คำตอบที่บันทึกไว้และแสดงข้อความล่าสุด

## ผลที่ได้และขอบเขต

- ตรวจ 44 รายการจาก Kursbuch, Arbeitsbuch, Grammatik A1 – das Training และ Grammatik aktiv. จำนวนนี้รวมข้อย่อย ตัวอย่างที่พิมพ์เฉลยไว้ และกิจกรรมตาราง/อ่านข้อความ จึงไม่ใช่จำนวนโจทย์ที่พร้อมนำเข้าเว็บ
- GT บท 32 หน้า 57 ตรวจทั้งหกบทสนทนาและแจกแจง 22 ตำแหน่งคำตอบ รวมช่องตัวอย่าง. AB L13/7b แจกแจงตำแหน่งบุคคลในตาราง และ 7a บันทึกคู่กริยากับสรรพนามที่พบทั้งแปดคู่
- เขียนโจทย์เว็บใหม่ 15 ข้อ: เลือกคำ 5, พิมพ์รูปคำ 8, เรียงคำที่ให้มา 2. แบบพิมพ์ครอบคลุมรูป mir, dir, ihm, ihr, uns, euch, ihnen, Ihnen ครบแปดรูป
- ต้นแบบ HTML เปิดในเบราว์เซอร์ได้โดยตรง ไม่มีการเรียกเซิร์ฟเวอร์หรือใช้ข้อมูลบัญชีผู้เรียน. ผลจำลองเก็บใน localStorage ของต้นแบบเท่านั้น
- เปิดเฉพาะเมนู Practice ของบัญชีทดลอง ยังไม่ได้เขียน exposure/attempt ลง Supabase และไม่ได้ตรวจรายข้อครบ L13–L18. ไม่มีโจทย์ Schreiben ที่อ้างว่าตรง Dativ โดยไม่มีหลักฐาน

## หลักฐานที่เปลี่ยนข้อสรุปเดิม

1. Grammatik aktiv บท 23 หน้าพิมพ์ 58/PDF 54 มีป้าย **A2**. กริยา helfen/gefallen/gehören เกี่ยวข้องกับ L13 แต่ข้อในหน้านี้ให้ประกอบประโยคกับคำนามและ Dativartikel. ใช้เป็นแนวสร้างประโยคได้หลังลดภาระนั้น ไม่เปิดทั้งบทให้ L13
2. Grammatik aktiv 21/3 หน้าพิมพ์ 54/PDF 50 ทั้งหกข้อใช้กรรม Akkusativ และ Dativ ร่วมกัน. คำว่า "Dativ-pronoun cloze" ใน metadata เดิมยังอธิบายภาระของโจทย์ไม่ครบ จึงแก้หมายเหตุหลักฐานเดิม
3. GT 32/1/3 ตรง L13 เฉพาะสองช่องแรกที่ใช้ gehören. อีกสองช่องเป็น Nominativ. การจับคู่ต้องลงถึงช่องในบทสนทนา
4. AB 13/6 มีสรรพนามให้แล้วและถามรูปกริยา. จัดเป็นทักษะข้างเคียง ไม่ให้เครดิตว่าเลือกสรรพนามเองได้
5. uns/euch มีรูปเหมือน Akkusativ. ข้อที่ตอบสองรูปนี้ถูกให้หลักฐานเรื่องการสร้างรูปตามบุคคล แต่ยังแยกไม่ได้ว่าผู้เรียนรู้ Case หรือจำรูปมา

ตรวจ SHA-256 ของ PDF ทั้งสี่เล่มในรอบนี้ตรงกับทะเบียน `src/lib/source-catalog.ts`. หน้าที่เปิดคือ KB 11/PDF 11, AB 8/PDF 7, GT 57/PDF 57 และ GA 54–55/PDF 50–51, 58–59/PDF 54–55. หน้า GA 59 ถูกเปิดดูเพื่อกำหนด backlog เท่านั้น ไม่มีรายการจากหน้านี้ได้รับสถานะตรวจรายข้อแล้ว. ไม่อนุมานเลขหน้าจาก offset ทั้งเล่ม

## ข้อกำหนดการฝึกในต้นแบบ

ผู้ตรวจเปิดหัวข้อ เลือกรูปแบบและจำนวน แล้วกดเริ่ม. ค่าเริ่มต้น 5 ข้อ; เลือก 10 หรือทั้งหมดได้. ถ้าเลือกรูปแบบเรียงคำซึ่งมีเพียงสองข้อ ระบบแสดงว่ารอบนี้มีสองข้อ แม้เลือกจำนวนสิบ. แต่ละข้อเก็บ snapshot ของโจทย์ ตัวเลือก คำที่เรียง ลำดับคำ คำตอบร่าง และสถานะเฉลย

| รูปแบบ | การใช้งาน | หลักฐานที่ได้ | สิ่งที่ยังสรุปไม่ได้ |
|---|---|---|---|
| Choice, 5 ข้อ | แตะตัวเลือก เปลี่ยนได้ก่อนตรวจ กดตรวจ แล้วเลือกความมั่นใจเมื่อถูก | แยกตัวเลือกตามบุคคลและ Case | การพิมพ์รูปคำเอง |
| Cloze มีบุคคลกำหนด, 6 ข้อ | แตะช่อง พิมพ์หนึ่งคำ กด Enter หรือปุ่มตรวจ | สร้างรูปสรรพนามจากบุคคลที่ระบุ | การตีความผู้ถูกอ้างถึงโดยไม่มีคำใบ้บุคคล |
| Cloze จากบริบท, 2 ข้อ | อ่านสถานการณ์ พิมพ์หนึ่งคำ แล้วตรวจ | เปลี่ยนบุคคลหลายคนเป็น ihnen และใช้ Ihnen ในบริบทสุภาพ | การเขียนประโยคอิสระหรือการใช้ทุกบุคคลจากบริบท |
| Word order, 2 ข้อ | แตะคำลงพื้นที่ประโยค แตะนำกลับได้ แล้วตรวจ | วางคำที่ให้มาตามคำสั่งขึ้นต้นประโยค | การเรียกคืนสรรพนามหรือผันกริยาเอง เพราะคำทั้งหมดให้มาแล้ว |

การเรียงคำกำหนดคำขึ้นต้นชัดเจนเพื่อให้เฉลยที่กำหนดไม่ตัดประโยคเยอรมันลำดับอื่นที่ยังถูกไวยากรณ์. ไม่บังคับลาก จึงทำได้ด้วยนิ้ว เมาส์ และปุ่ม Tab/Enter. ทุกปุ่มมีข้อความ ไม่ใช้สีเพียงอย่างเดียวสื่อถูกผิด. ปุ่มตรวจปิดจนกรอกหรือเรียงครบ

เมื่อส่งคำตอบ ต้นแบบต้องบันทึกสำเร็จก่อนแสดง feedback. ถ้าบันทึกไม่ได้จะแจ้งให้ลองบันทึกอีกครั้งและยังไม่สร้าง attempt. เมื่อตอบผิดแสดงเฉลยกับเหตุผลทันที. เมื่อตอบถูกให้เลือกง่าย/ต้องคิด/เดา; ก่อนเลือกถือเป็น Pending และกลับมาที่ขั้นเดิมได้หลัง reload. การส่งซ้ำไม่สร้างผลใหม่ในช่องเดิม

หลังเฉลยปิดการแก้คำตอบของข้อนั้นและกดข้อต่อไป. การลองใหม่เป็น session ใหม่ ตาม baseline. ไม่เพิ่มปุ่มแก้ตัวในช่องเดิมที่ทำให้ first-attempt score เปลี่ยน. คำใบ้ก่อนตอบถูกเก็บแยกจากคำตอบที่ทำได้เอง. ตัวเลือกและคำในโจทย์คือ built-in support แม้ผู้เรียนไม่กดคำใบ้

## การสุ่มและจำนวน

ต้นแบบใช้ topic เดียว มี 15 ID ที่ไม่ซ้ำกัน. รอบใหม่เลือก ID ที่ยังไม่เคยจัดเข้า session ก่อน แล้วเลือกข้อที่จัดให้นานที่สุด. ในกลุ่มที่มีประวัติเท่ากันกระจายชนิดโจทย์และสุ่มตัวเลือก. เมื่อได้ชุดแล้วเรียงกิจกรรมเลือกคำก่อนเติมคำและเรียงคำ. ดังนั้น "สุ่ม" ไม่ได้แปลว่าทุกตำแหน่งมีความน่าจะเป็นเท่ากัน

- ถ้าคละรูปแบบเดิมสามรอบ รอบละห้าข้อ จะครอบคลุม 15 ข้อโดยไม่มี ID ซ้ำ. หลังจากนั้นเริ่มวนข้อเก่าได้
- การกดเริ่มแล้วออกกลางทางถือว่าชุดนั้นถูกจัดให้แล้ว แม้ยังไม่ตอบครบ; ลดการจัดชุดเดิมซ้ำเมื่อเปิดรอบใหม่
- กลับมาทำ session เดิมใช้ snapshot เดิม ไม่สุ่มคำตอบหรือลำดับใหม่. ชุดที่ยังไม่จบเก็บแยกไว้และเลือกทำต่อได้
- รอบทบทวนจากสรุปเลือกข้อผิด/ข้อที่ตอบถูกแต่ต้องคิดหรือเดาใน session นั้น. ต้นแบบยังไม่ได้ทำคิวทบทวนสะสมข้ามทุก session
- ต้นแบบยังไม่มี variant ที่เทียบเท่ากันหลายข้อในทุก subskill จึงไม่อ้างว่ารอบทบทวนจะใช้ประโยคใหม่เสมอ

เป้าหมายประมาณ 180 ข้อแรก/288 ข้อระยะถัดไปจากการสนทนาเป็นเป้าหมายวางแผน A1.3 ทั้งชุด ไม่ใช่จำนวนที่สร้างแล้ว. ตอนนี้มี **15 ข้อใหม่ในคลังต้นแบบ**. ตัวเลือก 20 ข้อจะมีความหมายเมื่อ pool ที่เข้าเงื่อนไขมีมากพอ; pilot นี้ยังไม่เพิ่มตัวเลือกดังกล่าว

## การตรวจคำตอบและข้อจำกัดการวิเคราะห์ความผิด

ใช้ NFC, ตัดช่องว่างหัวท้าย, ยุบช่องว่างต่อกัน และไม่เคร่งเครื่องหมายท้ายประโยค. คงตัวพิมพ์เล็กใหญ่ เพราะ ihnen กับ Ihnen ต่างกัน. ไม่เปลี่ยนตัวสะกดเยอรมันหรือแก้คำอัตโนมัติ

`knownErrors` ระบุเฉพาะคำตอบผิดที่วิเคราะห์ไว้ เช่น mich แทน mir เกี่ยวกับ Case และ ihnen แทน Ihnen เกี่ยวกับรูปสุภาพ/ตัวพิมพ์. คำตอบอย่าง ihr อาจเป็น Nominativ ของผู้ฟังหลายคนหรือ Dativ ของผู้หญิง จึงบันทึก `case_or_referent` เมื่อหลักฐานแยกไม่ได้. ข้อความอื่นที่ไม่รู้จักใช้ `unclassified`; ไม่เรียกคำผิดทุกคำว่า spelling error และไม่เดาสาเหตุทางความคิดของผู้เรียน

Feedback ในต้นแบบอธิบายบุคคลและรูปที่ต้องใช้. รหัสวิเคราะห์ใช้ตรวจข้อมูลภายในและยังไม่สร้าง dimension evidence ในระบบจริง. ข้อเปิด/เขียนอิสระยังไม่อยู่ใน pilot เพราะยังไม่มีตัวตรวจหลายคำตอบหรือ rubric ที่พร้อมใช้. แบบเรียงคำไม่ถูกนับแทนการเขียนอิสระ

## ข้อมูลที่ต้องเชื่อมกับระบบจริง

| ข้อมูล | ตำแหน่งในงานนี้ | การใช้เมื่อเชื่อมระบบ |
|---|---|---|
| หลักฐานแหล่งและสถานะ | source-items + provenance | ตรวจย้อนกลับภายใน ไม่ส่งเข้า learner copy |
| ID และเวอร์ชันโจทย์ | bank | เก็บใน SessionItem snapshot เพื่อเฉลยตามเวอร์ชันที่ผู้เรียนทำ |
| Topic และ prerequisite | bank | กรองด้วยหลักฐานเรียนจริงก่อนเปิด Practice |
| รูปแบบและ subskill | bank | แยกการเลือกคำ การสร้างรูปคำ และการเรียงคำ |
| คำตอบครั้งแรก/คำใบ้/ความมั่นใจ | state ต้นแบบ | ต้องแปลงเป็น LearningAttempt/AttemptEvidence ตามสัญญาจริง |
| ลำดับข้อ/ตัวเลือก/ร่างคำตอบ | state ต้นแบบ | ทำต่อได้โดยไม่สุ่มใหม่ |
| ความผิดที่อธิบายได้ | knownErrors | แปลงเป็น dimension ที่มีหลักฐาน ไม่ให้เครดิตทุกทักษะจากคะแนนรวม |

Topic IDs ใช้ของเดิม `L13-dativ-pronomen` และ `L13-verben-mit-dativ`. การมีชื่อ topic ในไฟล์ไม่ใช่ exposure. ก่อนเปิดในเว็บต้องกำหนดการผูกกับ item IDs ที่มีหลักฐานเรียนจริง และตรวจศัพท์ที่ใช้ในแต่ละข้อด้วย. ห้ามสร้าง exposure ให้โจทย์ใหม่จากการ import เพียงอย่างเดียว

Practice หลักใช้ `item_exposures`, `practice_sessions`, `session_items`, `learning_attempts`, `attempt_evidence`; กิจกรรม course L13/L14 มี state ของตน. Bank นี้ยังไม่เพิ่ม storage เส้นทางที่สามในแอป. ต้นแบบแยกชัดเจนว่าไม่ส่งผลจริง

ตอนนำเข้าจริงให้ใช้ Practice shell เดิมและตัวแสดง choice/cloze/order ที่มีอยู่ โดยต้องตรวจความต่างต่อไปนี้ก่อน:

1. `SessionItem` ปัจจุบันต้องอ้าง item ที่มี exposure. ต้องผูก concept/item เดิมกับ question ID ที่เปลี่ยนได้ในแต่ละรอบโดยไม่สร้างประวัติเรียนเทียม
2. Review ปัจจุบันดู Completed attempt ล่าสุดต่อ item. หากเอาทั้ง choice และ production ผูก item เดียว ความสำเร็จจาก choice อาจกลบข้อผิด production. ต้องกำหนดขอบเขต subskill ของ Review และบันทึกผลกระทบใน baseline/changelog ก่อนเปลี่ยนกฎจริง
3. ชุด `L13-AB-DATIV-BANK` ที่มีอยู่แล้วครอบคลุมรูปสรรพนามหลายรูป. ข้อใหม่เพิ่มความหลากหลายของคลัง ไม่สร้างหัวข้อ Dativ ซ้ำอีกทาง. ต้องคง IDs และ attempts เดิม
4. การแก้เฉลยในอนาคตเพิ่ม version ของคำตอบและเก็บ snapshot เก่า. ไม่คำนวณคะแนนประวัติเดิมย้อนหลังเงียบ ๆ
5. การล้างข้อมูลต้นแบบหรือเริ่มใหม่ต้องไม่มีผลต่อ Supabase/บัญชีจริง. การย้ายผลทดลองนี้เข้าสู่ Learning History ไม่อยู่ในแผน

## วิธีสร้างและตรวจซ้ำ

ใช้ Node 20 ขึ้นไปที่ทำงานได้ในเครื่อง. ใน workspace นี้ใช้ `.tools/node-v20.20.2-darwin-x64/bin/node`; Node เริ่มต้นใน shell เป็น 18 จึงไม่รองรับ Playwright รุ่นที่ติดตั้ง. ไม่แก้ system/shell configuration

```sh
node --import tsx scripts/exercise-mapping/validate-data.mjs
node scripts/exercise-mapping/build-preview.mjs
node scripts/exercise-mapping/verify-preview.mjs
```

Browser script ใช้ Chrome ในเครื่อง หรือรับ `CHROME_PATH`. เปิด HTML ด้วย file URL และใช้ browser context ใหม่ ไม่มีการเชื่อม production. ตรวจครบ 15 ข้อ คำตอบถูก/ผิด Ihnen/ihnen, คำใบ้, confidence, reload ขณะ Pending, ส่งซ้ำ, สุ่มสามรอบไม่ซ้ำ, pool น้อยกว่าจำนวนที่ขอ, ทบทวนผิด/เดา, การบันทึกล้มเหลว และหน้าจอกว้าง 1280/แคบ 320 พิกเซล. ภาพผลตรวจเก็บใน `.tools/a13-item-audit/screenshots/` ไม่เผยแพร่ภาพหน้าหนังสือ

รอบนี้รัน `node --import tsx --test tests/source-metadata.test.ts` เพิ่มด้วย เนื่องจากแก้หมายเหตุและเพิ่มหลักฐานใน source catalog ที่ระบบใช้อยู่. ผ่านทั้ง 11 tests รวมการตรวจ source registry, การคง IDs/ประวัติเดิม และ CLI ที่อ่าน metadata

การตรวจอัตโนมัติพิสูจน์ความสอดคล้องของข้อมูลกับการทำงานของต้นแบบ ไม่ได้พิสูจน์ผลสัมฤทธิ์ทางการเรียนหรือใช้แทนการตรวจเนื้อหาโดยครู
